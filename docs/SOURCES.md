## Phase 2 live update, checked 2026-11-16–17 UTC

Latest official registry at 2026-11-17T15:07:10.149Z: **686 identities, 379 online and 307 offline**. The 02:34 observation was 378/308, demonstrating changing membership/status rather than a fixed count.

Official REST registry/exchange/ticker/depth/klines were tested live after diagnosing WSL's failing 10.255.255.254 DNS resolver. `PROVIDER_DNS_SERVERS=1.1.1.1` is an optional process-local standard resolver override, preserving official hostnames, SNI and TLS verification. No system resolver was changed, no proxy/geographic bypass was used. Actual registry: 686 identities (377 online/309 offline); actual exchange-info: 1,467 symbols and U/USDT/USDC quotes. Rate-limit metadata and serverTime were absent, not fabricated. Raw hashes/UTC capture timestamps and separate source kinds are stored. The original runtime failures below are historical.

The official [Alpha JavaScript SDK](https://github.com/binance/binance-connector-js/tree/master/clients/alpha) was verified as Binance-owned; REST currently uses the typed lean adapter, not a streaming service claim. [Ethereum JSON-RPC](https://ethereum.org/developers/docs/apis/json-rpc/), [BSC RPC guidance](https://docs.bnbchain.org/bnb-smart-chain/developers/json_rpc/json-rpc-endpoint/) and [Base connectivity documentation](https://docs.base.org/get-started/connect-to-base) were reviewed. Public BSC/ETH reads produced real evidence; later historical access failed. Base public log retrieval remains 429-limited despite working metadata/head calls.

Passive trade interpretation uses [official Pancake V3 factory addresses](https://developer.pancakeswap.finance/contracts/v3/addresses) and the [exact event interface](https://github.com/pancakeswap/pancake-v3-contracts/blob/main/projects/v3-core/contracts/interfaces/pool/IPancakeV3PoolEvents.sol), including its extra protocol-fee words. DEX Screener's documented token-pairs API supplies candidate pools only; on-chain factory registration must validate each. One attributed buy, one attributed sell and sixteen unattributed pool-side swaps observed; no transfer-only purchase inference.

Complete setup/quota/cost/caveats: [API_SOURCES_AND_SETUP.md](API_SOURCES_AND_SETUP.md). Official hosting and Neon pricing was checked for [WORKER_HOSTING_COMPARISON.md](WORKER_HOSTING_COMPARISON.md). No provider subscription or hosting plan activated. Trial credits/temporary account offers are not assumed permanent. Current account-specific usage/terms remain operator checks.

The Alchemy RPC environment variable names are `ETH_RPC_URL`, `BSC_RPC_URL`, `BASE_RPC_URL`, `ARBITRUM_RPC_URL`, and `SOLANA_RPC_URL`. At the latest env check on 2026-11-17, only `BSC_RPC_URL` and `BASE_RPC_URL` were set (hostnames were confirmed as the Alchemy mainnets without printing URL paths/credentials); the other three variables were unset. Keep them in ignored `.env.worker.local` and never expose them in the browser/logs. Worker defaults may use public read endpoints when a variable is missing, but Alchemy diagnostics require the explicit Alchemy URL so fallback cannot be mistaken for a credential test.

For exact free-tier Alchemy log behavior, see [Alchemy `eth_getLogs` range limits](https://www.alchemy.com/docs/chains/ethereum/ethereum-api-endpoints/eth-get-logs) and [archive-state explanation](https://www.alchemy.com/docs/what-is-archive-data-on-ethereum). The worker clamps requests to ten blocks on Alchemy regardless of a higher `SCAN_BLOCKS` setting. This avoids known range-limit errors but is not enough to reconstruct broad, current multiweek histories at one-hour per-token cadence; the cursor can fall behind chain head. No complete-history claim is made. Measure cursor lag and CU use before increasing cadence or choosing an indexed transfer API.
