## Host decision

Recommend **Render Starter Background Worker, $7/month**, for predictable worker compute pricing and managed restarts. Its 512 MB / 0.5 CPU envelope fits the measured Node process (recent broad collection mean about 158 MiB, peak 185 MiB, CPU about 5.7% of one core); allow loader/native buffers and validate a full hosted cycle before declaring capacity accepted. The existing small/failed profiles are not a production soak. No inbound domain, HTTP service, Redis, second database or persistent disk is required.

**Railway Hobby is the cheaper managed alternative, approximately $5/month minimum** for this measured workload: `max($5, RAM GB × $10 + vCPU × $20 + egress GB × $0.05)`. For 0.16–0.25 GB and 0.02–0.06 vCPU this is approximately $2–$3.70 resources before the $5 floor. Container overhead, egress and catch-up spikes can increase it; a hard spending cap can stop collection. Render gives a simpler fixed compute bill. A small Docker VM adds OS/security/backup maintenance and is not needed merely to reuse Neon. Oracle's earlier account/availability blocker remains unresolved; it is not dependable free capacity.

Sources checked today: [Render pricing](https://render.com/pricing), [Render worker plans](https://render.com/docs/compute-plans), [Railway pricing](https://docs.railway.com/pricing). Neither a Render nor Railway repository manifest existed at the starting release; the prior configurations were manual instructions plus Docker/systemd. This milestone adds a reviewable Render Blueprint and hardened Compose configuration. Railway's official docs now deprecate `railway.json`/`railway.toml`, with a December 1 cutoff, so no obsolete auto-discovered manifest was added. Use current [Railway IaC](https://docs.railway.com/infrastructure-as-code) or dashboard settings if choosing it.

## Implemented controls

- Additive migration `0014_worker_operations.sql` stores atomic UTC request/CU reservations, provider deferrals and operational alerts. Production migration applied to the existing Neon project; no reset or destructive migration.
- Every worker HttpClient attempt reserves before dispatch. Shared Alchemy daily/monthly CU ceilings survive restarts and chain changes. Concurrent reservations cannot exceed a ceiling; a refused multi-scope reservation rolls back partial charges. Unknown methods are refused. The old process request cap remains available for bounded diagnostics.
- Durable 403/429/transient-error cooldowns isolate providers. HTTP Retry-After is retained, including date form. Deterministic Solana JSON-RPC errors are not retried three times immediately or used to block every mint. Version errors receive a six-hour token-job retry.
- A five-minute operations job checks storage, registry freshness, stale/missing markets, overdue jobs, expired leases, EVM/Solana progress, provider cooldowns and CU usage. Alerts are durable, resolve on recovery, and deduplicate in-app notifications to at most one reminder per six hours. They are operational notices, not market signals. Telegram stays disabled.
- Container liveness reads its own fresh PID/heartbeat file without waking Neon. The process validates its dedicated advisory lock; heartbeat loss cancels provider reads, a watchdog bounds stalled liveness, and SIGTERM cancels reads then allows up to 75 seconds to drain. A separate 180-second startup watchdog bounds a stalled native connection before the first heartbeat; a real silent-TCP regression verifies termination. Job deadlines, lease expiry and cursor/event deduplication preserve recoverable progress.
- The new revision waits up to two minutes for lock handover; one-shot diagnostics still refuse an occupied collector. Exactly one collector owns the lock. Startup preflight rejects pooled-worker URLs, mismatched targets, absent TLS/RPC config, unapplied migration, paid enrichment and accidental diagnostic time/request limits.
- Request auditing reuses the existing raw-SQL pool, avoiding the additional ORM connection on the worker's request path. Profiling still distinguishes local process usage from database server/billing metrics.
- Docker includes the required driver patch before frozen installation, declares tsx as a worker runtime dependency, and installs worker production dependencies only. Nonroot/read-only execution, no published ports, memory/CPU limits and log rotation are retained.
- Optional hourly GitHub heartbeat/critical-alert workflow is **disabled unless** `FLOWNIX_WORKER_HEALTH_ENABLED=true`. It requires a monitoring database secret and makes no hosting/billing change. Configure GitHub workflow failure notifications after activation; worker-local alerts alone cannot report their own process's death.

Remaining gates are approval/capacity reconciliation, reliable hosted native database connectivity, a full supported-universe and paired-market cycle/soak, recovery of interrupted Solana jobs with all account gaps preserved, missing adapters for 21 current identities, and a budgeted design for continuous chain-time collection instead of perpetually lagging ten-block cursors.
